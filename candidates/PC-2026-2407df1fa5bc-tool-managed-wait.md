# Ожидание длительной операции внутри инструмента

- **Когда применять:** агент ждёт сборку, тесты, пакетную обработку или внешний
  прогон, а промежуточный статус сам по себе не меняет действий.
- **Промпт / паттерн:** перед запуском проверь способ дождаться завершения.
  Держи цикл проверок внутри инструмента и сохраняй ID запуска и итог.
  Возобновляй работу модели при успехе, ошибке, таймауте или когда нужно
  решение. При обрыве транспорта сверяй статус по ID перед повторным запуском.
- **Почему работает:** на стенде инструмент дождался результатов обеих
  операций после HTTP-таймаута. Агент получил один ответ без проверки статуса
  в диалоге. Отдельно подтверждена доставка ошибки и таймаута ожидания.

## Notes

Для сравнения производительности 1С и длительной пакетной загрузки BI
достаточно одинакового контракта ожидания. Стендовое подтверждение есть для
1С. Проверка BI и многочасового ожидания остаётся открытой.

Для регрессии запустить тестовую операцию дольше транспортного таймаута.
Проверить один запуск по ID, один итоговый ответ и отсутствие промежуточных
вызовов модели. Повторить для ошибки и срока ожидания. При ограничении времени
инструмента объединять проверки внутри доступного интервала.
