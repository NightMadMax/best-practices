# Запуск отладки EDT без обновления конфигурации ИБ

- **Контекст:** отладка 1С запускается программно — через MCP, CLI или
  собственную автоматизацию — и конфигурация информационной базы должна остаться
  как есть.
- **Проблема:** EDT показывает модальный диалог обновления приложения, и кнопка
  по умолчанию в нём обновляет конфигурацию базы. Автоматика, которая жмёт кнопку
  по умолчанию или ждёт, пока окно исчезнет, меняет состояние базы молча — на
  общей базе это изменение получают все, кто с ней работает. Запуск при этом
  выглядит успешным, поэтому ошибку замечают позже, чем она произошла.
- **Решение:**
  1. Подтверждать только точно опознанную кнопку запуска без обновления, по её
     подписи в каждой поддерживаемой локали.
  2. Подпись не найдена — отменять диалог. Кнопка по умолчанию в этом режиме
     запрещена: несостоявшийся запуск дешевле незаявленного изменения базы.
  3. Ставить перехватчик только на время вызова запуска и снимать его в
     `finally`, иначе он переживёт неудачный запуск.
  4. При пересечении параллельных запусков отдавать приоритет варианту, который
     базу не изменяет.
- **Проверка:** сравнивать не факт запуска, а состояние базы. Признак
  необходимости обновления, который EDT возвращает по проекту, обязан остаться
  прежним после запуска, а в журнале EDT — присутствовать запись о нажатии именно
  кнопки запуска без обновления.

## Notes

Практика описывает контракт поведения, а не реализацию: доработка MCP EDT —
только один способ его выполнить. Диалог принадлежит EDT, а не конкретной
конфигурации, поэтому урок повторяется в любом проекте с программным запуском
отладки.

Если инструмент запуска обновится, сначала проверить, вошло ли поведение в
поставку, и только потом отказываться от локального решения: молчаливый откат к
кнопке по умолчанию вернёт исходную проблему.
